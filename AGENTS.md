# Local Agent Companion development guide

This integration branch combines Game Design with upstream `a6f3977` on candidate
engine 1.1.0 / clients 0.13.0. The original Game Design checkout is preserved.
Do not confuse old installed evidence with this candidate. Mac provider policy
is awaiting the user's clarification: upstream allows explicit Ollama/OpenAI
selection while the earlier suite plan restricted Mac to Ollama. Keep candidate
preparation separate from activation; do not infer consent to enable a provider,
perform real inference, merge or promote a release from local tests.

Model settings use a legacy-compatible base row plus namespace/provider/account
feature storage. Keep the original validated migration text and atomic revision
checks; never strip unknown fields or restore another account's web permissions.
Read the current section of [rollback](docs/GAME_DOMAIN_ROLLBACK.md) before activation.

Browser supervisor temporary directories are operation-owned (`temporary.ts`).
Their optional private journal binding covers owner/device/inode; no RPC accepts
the path. The worker validates the closed temporary/AppData environment. Keep
legacy receipts readable and require bound shutdown plus absent original worker
before deleting external temporary resources; unknown work retains them. The
test-only never-browser fixture may explicitly remove its own directory after
asserting production refusal. Preserve actual rendering/animation assertions;
pixel palette size is diagnostic, not a quality or hardware acceptance gate.

GitHub-hosted Intel Mac tests (no usable WebGL GPU). Keep this test-only and
keep sandboxing; never propagate software-driver flags into preview/collectors,
RPC or game recipes. A software CI rendering is not physical GPU acceptance.
